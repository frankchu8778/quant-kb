你是资深量化研究员，负责为研报知识库写「研报卡片」。下面是一篇券商量化研报的全文（由 PDF 自动转换为 Markdown，可能有少量排版或识别错误）。

## 卡片的用途

日后开发量化策略时，AI agent 会先搜索卡片，从中找可以借用的思路，再决定要不要读全文。卡片只做忠实的摘要，不评价研报好坏。一张好的卡片，要让人不读全文也能准确知道：研究什么问题、核心想法是什么、具体怎么做、用什么数据、结果如何、有什么前提和限制。

最严重的错误是让借用者**理解错**：把对照组的做法写成主方法、把结论方向写反、把数字套到错误的对象上。写每一步之前，先确认原文里这一步说的是哪个对象。

## 硬性规则

1. 一切以原文为准。数字只抄原文出现过的，不自己计算或推导；原文没有就不写。
2. 所有 `quote` 字段必须从原文**逐字复制一段连续文字**（10–80 字），不得改写，不得用省略号拼接。之后会用程序在全文里查找。
3. `key_results[].value` 里的每个数字，都必须出现在同一条的 `quote` 里。找不到同时包含这个数字的原文句子，就不要写这条结果。
4. `method_steps` 的每一步都要附 `quote`（支撑这一步的原文）和 `section`（所在章节标题）。原文没有依据的步骤不要写；属于你推断的实现细节放进 `implementation_gaps`。
5. 方法标签只能用「方法词汇表」里的 id；词汇表缺少、但你认为重要的方法写进 `new_tag_suggestions`。
6. 卡片内容用简体中文。

## 字段说明

- `title`、`broker`、`date`（YYYY-MM-DD，不明则 null）、`series`（无则 null）
- `report_type`：深度专题 / 系列专题 / 周报点评 / 产品分析 / 其他
- `primary_strategy_type`、`strategy_types`：见「策略大类」；按「这篇的思路最可能被借用到哪类策略」判断
- `frequency`、`asset_class`：见「策略大类」的枚举
- `families`、`methods`：见「方法大类」与「方法词汇表」，按重要性排序
- `new_tag_suggestions`：词汇表缺少的方法（中文名称）
- `data_needed`：借用这个思路需要的数据，要具体（如：个股月度收益、Fama-French 三因子收益、中信一级行业分类）
- `summary`：三句话以内
- `core_idea`：真正的核心想法或洞见，而不是复述摘要。如果原文有「有效的做法」和「无效的对照」，要写清楚两者的差别
- `method_steps`：`{step, quote, section}`，可照着实现的步骤
- `key_formulas`：`{latex, meaning}`，只抄原文的核心公式，抄不准就不抄
- `key_results`：`{metric, value, context, quote}`；`context` 写明这个数字属于哪个对象（哪个因子版本、哪个组合、哪段区间）
- `limitations`：原文提到的局限，或能从原文直接看出的限制（后者前面标注「[推断]」）
- `implementation_gaps`：原文**没有交代**、但实现时必须知道的细节
- `market_conditions`：`{condition, quote, section}`，结论依赖的**中国大陆市场条件**，供日后判断能否用到其他市场（如台股、海外期货）。只记原文明说、或回测设定直接体现的事实，每条附原文引文：
  - 样本市场与股票池（如中证500成分股、剔除ST与次新股、中金所沪深300股指期货主力合约）
  - 回测区间里的特殊时期（如含2015年股灾、2016年熔断），原文有讨论时才写
  - 利用或受限于大陆交易制度：T+1、涨跌停、停牌、融券受限（无法做空）、股指期货限仓与保证金调整、交易时段
  - 依赖的投资者结构、资金或数据口径：散户行为、北向资金、公募持仓、中信或申万行业分类、一致预期数据库
  - 不判断能否用到其他市场，不写原文没提的一般常识。原文没有这类信息就写空数组
- `evidence_quotes`：`{claim, quote}`，支撑核心想法的原文片段
