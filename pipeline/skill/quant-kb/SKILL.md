# 量化研报知识库

知识库在 `/home/newt/quant-kb/kb/`，只读：由 quant-kb 项目的 `pipeline/publish.py` 生成。卡片与全文都是**简体中文**。

**省 token 是这份 skill 的核心要求**：不要自己 grep 或逐张读卡。一律先用 `kb-search` 在本机排序（不花 token），再按层往下读，够了就停。整张卡约 7,000 字，精简卡约 1,000 字，清单一行约 100 字。

## 工具：`kb-search`

装在 `~/.local/bin/kb-search`（源文件 `/home/newt/quant-kb/pipeline/kbsearch.py`）。

| 命令 | 作用 | 大约字数 |
|---|---|---|
| `kb-search search "问题" [--freq intraday] [--type trend-following] [--asset stock-index-futures] [--family machine-learning] [--since 2018]` | 语意＋关键词＋标签混合排序，列前 15 名，每篇一行：id、标题、频率、一句摘要、命中的词 | 约 1,500 |
| `… --all` | 列出所有符合筛选的卡（列表型问题，如「所有日内策略」） | 每篇约 100 |
| `… --brief N` | 顺便印出前 N 张的精简卡 | 每张约 1,000 |
| `kb-search brief <id> [<id> …]` | 精简卡：标签、原文文件名、摘要、核心思路、步骤标题、1–2 条关键结果、市场条件 | 每张约 1,000 |
| `kb-search card <id>` | 整张卡（每步附原文引文、公式、全部结果、局限、已知问题） | 每张约 7,000 |
| `kb-search grep <id> "正则"` | 只在这一篇的全文里找段落，最多 2 段、每段 ≤600 字 | ≤1,200 |

- id 可以只打最后 6 码。问题用简体或繁体都行；把问题用自己的话写完整，可以加同义词或英文（例如「开盘区间突破 opening range breakout」），不用写正则。
- 第一次 search 要等约 15 秒启动本机服务，之后不到 1 秒。周报点评一律不列。
- 筛选值：频率 `high-frequency`、`intraday`、`daily`、`weekly-or-longer`、`unspecified`；策略大类、方法家族、方法的 id 见 `kb/VOCAB.md`（只在要用筛选、又不确定 id 时才读）。

## 步骤

0. **策略笔记**：只在使用者明说要迭代、推进某个策略的开发时才用（例如「继续做 XX 策略」「把这个记进 XX 的笔记」）：先读 `/home/newt/quant-kb/workspace/<策略名>/notes.md`，笔记里「已读研报」有的不再重读那张卡，除非问题需要笔记没记的细节。只是问「有什么方法、有什么特征」这类查资料的问题，即使提到自己想做某个策略，也**不建、不读、不写**笔记；不确定时不写，回答末尾问一句要不要记进笔记。
1. **搜索**：`kb-search search "<问题>"`，问到频率、资产、策略大类时加筛选。列表型问题用筛选＋`--all`，读清单就能答，不必读卡。一个问题最多换 2 种说法各搜一次。
2. **看清单**：看完整张清单（不只前几名），按标题、一句摘要、命中的词挑出可能相关的。排名后面但摘要明显相关的也要挑。
3. **读精简卡**：`kb-search brief <挑出的 id>`，最多 8 张。多数「有没有、谁做过、大概怎么做」的问题到这里就能答。
4. **读整卡**：只有遇到具体问题（要照着实现某个方法、要完整参数或全部结果、精简卡标了已知问题）才 `kb-search card <id>`，每题最多 3 张。
5. **回原文**：只在两种情况下：卡片没写问题需要的数字、参数或条件；或卡片前后矛盾。用 `kb-search grep <id> "<关键词>"`，只看这一篇。其他情况不读原文，把原文文件名与章节告诉使用者，推导过程由使用者自己看原文。卡片和原文不一致时以原文为准。
6. **更新策略笔记**（只在第 0 步确定要用笔记时）：见下。
7. **回答**，格式见下。

**预算**：一般问题读进约 1 万字（清单＋几张精简卡），深入时约 3 万字（再加 2–3 张整卡）。要超过 3 万字时先停下，列出还没读的候选和各自为什么可能有用，问使用者要不要继续。

## 策略笔记

位置 `/home/newt/quant-kb/workspace/<策略名>/notes.md`（不在 `kb/`，发布不会覆盖；属于使用者的研究资料，不进 git）。没有就建一份：

```markdown
# <策略名> 开发笔记

## 目标与现状
（使用者要做什么、目前做法、卡在哪；对话中有变化就更新）

## 已读研报
### [<id>] <标题>
- 原文：`<source_pdf>`
- 要解决的问题：
- 方法：（一两句，够让之后的 agent 不必重读卡片就知道怎么做）
- 可借用：
- 对本策略：（适不适用、要改什么、要注意的市场条件）
- 读到哪层：精简卡／整卡／原文段落（日期）

## 决定与待办
- <日期>：<决定或待办>
```

每读完一张**相关**的卡（精简卡或整卡），在「已读研报」加一条，每条 3–5 行；已有的条目读了更深的层级就补充，不要重复加。使用者做了决定（采用、放弃、要测试什么）就记进「决定与待办」。看过但不相关的卡不记。

## 市场范围

全部研报来自大陆券商，实证几乎都在 A 股或国内期货上，库里没有台股、美股、CME 等海外市场的实证。问题针对其他市场时：

- 方法（因子构造、信号、检验流程）可以借；收益、IC、最优参数只代表原文的市场与区间。
- 找出结论依赖的大陆市场条件：T+1、涨跌停、融券难、停牌与 ST、股指期货 2015 年后的限仓、散户占比、小市值与壳价值、指数成分股效应、股灾等特殊时期。精简卡有「市场条件」就以它为准；没有时从步骤、结果的条件判断，必要时 `kb-search grep <id> "涨跌停|停牌|T\+1|融券|做空|ST|股灾|限仓|散户|成分股"`。
- 完整清单与各市场差异见 `kb/CLAUDE.md` 的「市场范围」。

## 可信度

- 整卡「」里的引文是逐字原文，程序核对过。卡片与精简卡的叙述是摘要，可能有遗漏。
- 数字以原文为准；引用时带上条件（样本期、股票池、是否含交易成本）。
- 清单或精简卡标了「已知问题」：用到相关部分前读整卡末尾的「已知问题」，并在回答里说明。
- 精简卡的「核对：revised」表示核对时被退回、重写后才通过。

## 回答格式

1. 直接回答：结论、**可以借用的方法**、对使用者策略的意义。每个结论标来源卡片 id，例如 `[20190610_国信证券_1818e6]`。不复述研报的推导过程。
2. 关键数字附条件。讲特征、因子或信号时，写清它在什么**市场状态**下有效或失效（趋势／震荡、波动高低、牛熊或特殊时期、大小盘风格、样本期与品种），卡片没写的就说没写，不要只列特征名。
3. 回答末尾附「引用的研报」表：卡片 id、研报标题、**原文文件名**（`source_pdf`，原样照抄，不要改字或繁简转换，方便使用者在自己的文件夹搜索原文）、所在子文件夹（精简卡「原文」后括号里的）、建议看的章节（有的话）。
4. 列出「看过但不相关」的候选 id，各附一句理由；再列「排名靠后、没细读但可能相关」的 id。
5. 问题针对 A 股、国内期货以外的市场时，加一段「市场差异」：列出结论依赖的大陆市场条件，标明「未在目标市场验证」。
6. 只陈述卡片或原文里有的内容。知识库里没有的，明说「知识库里没有」，再给最接近的卡；要补充一般知识时，标明那是一般知识、不是研报结论。
7. 最后一行写这次读进了哪些层（例如「清单 1 次、精简卡 6 张、整卡 1 张」），方便使用者掌握消耗。

## kb-search 不能用时

例如 `~/venvs/kb-parse` 不在：退回旧做法——在 `kb/catalog.jsonl` grep 标签与 frequency、在 `kb/cards/` grep 简体关键词，候选卡先只读「## 摘要」到「## 方法步骤」之间（`sed -n '/^## 摘要/,/^## 方法步骤/p'`），并告诉使用者工具坏了、这次比较耗 token。

## 更新

知识库随 quant-kb 项目的发布更新（`publish.py publish <batch>`，会顺便更新 `kb/index/` 的向量索引）。这份 skill 的源文件在 `/home/newt/quant-kb/pipeline/skill/quant-kb/`，`~/.claude/skills/quant-kb` 是指向它的链接。
